# tools/ — what is in here, and what actually runs

137 files. This is the index. It exists because the directory grew one problem at a time
and nothing said which of these are the pipeline and which are the archaeology.

**The short version:**

```bash
python3 tools/preflight.py          # the gate. Must print READY TO ORDER
bash tools/finish.sh                # design -> board -> fab outputs -> renders
bash tools/make_order_bundle.sh     # regenerate fab/ and zip the order
bash tools/build_firmware.sh        # build arducopter.apj
```

Everything else is either a **check** the gate already runs, a **generator** one of the
scripts above calls, or **construction history**.

---

## 1. The gate

`preflight.py` walks a manifest in `readiness.py` and derives the verdict from it. An unrun
tool, a non-zero exit, a failed check or an *unclassified* manifest entry is a blocking
failure — the verdict cannot be typed by hand. `python3 tools/prove_readiness.py` proves
that behaviour on synthetic inputs (20 assertions).

| tool | role |
| --- | --- |
| `preflight.py` | the gate: runs every check, prints the verdict |
| `readiness.py` | the manifest — every prerequisite, what proves it, what cannot be proven |
| `prove_readiness.py` | proves the manifest *blocks*. Not run by the gate; run it when you edit `readiness.py` |
| `audit_gate_patterns.py` | tests every regex in `preflight.py` against the text the tools actually print. Catches the class of bug where a tool's output format changes and the check silently falls back to a misleading message |

## 6. Construction history — not part of the pipeline

**Twenty-three of these are referenced by nothing.** They are the record of how the board
reached its present state, and at least one of them is load-bearing: `free_island_a.py` and
`free_island_b.py` are the *only* reproducible home of two placement fixes, and `finish.sh`
step 3d re-runs them because a `gen_pcb.py` rebuild re-creates the ground islands they
dissolve. Deleting them would silently lose those fixes.

So they are kept deliberately. Do not prune this list without checking that claim.

## 7. Known problems in this directory

All four verified by reading the files and the board, not by inference.

1. **`route.py`'s docstring describes a 4-layer board, but its constants are 6-layer.**
   The docstring says *"Layer plan: L1 signal + RF, L2 solid GND, L3 +3V3, L4 signal"* —
   the pre-`to_6layer` plan. The constants below it are current:
   `PLANE = {"GND": "In1.Cu", "+3V3": "In4.Cu", ...}` and
   `SIG_LAYERS = ("F.Cu", "In2.Cu", "In3.Cu", "B.Cu")`, which is exactly right for a
   6-layer board whose planes are In1 and In4. **Read the constants, not the prose.**
   Three tools import from it: `hand_route.py`, `route_connector_fan.py`, `route_final.py`.
2. **`route.py`'s via is not the via most of the board uses.**
   `VIA_D, VIA_DRILL = 0.60, 0.30`, commented *"JLCPCB standard 4-layer, no upcharge"* — a
   stale comment, since the board is 6-layer and `fab/ORDER.md` quotes 0.45 / 0.20. The
   board actually carries **two** sizes: **308 vias at 0.60 mm and 121 at 0.45 mm**. So a
   tool sizing a new via against `route.VIA_D` gets a legal 0.60 mm hole that is *not* what
   the smaller third of the board uses. Check which family you are joining before adding one.
3. **`route.py` breaks the docstring convention every other tool here follows.** Line 1 is
   blank, line 2 is `ISLAND_MAX_AREA = 50.0`, and the `#!/usr/bin/env python3` shebang is on
   line 3 — so the docstring is not the module's first statement and
   `ast.get_docstring()` returns `None`. Anything that indexes these tools by docstring
   (including the generator that produced this file) sees `route.py` as undocumented.
4. **`check_lcsc_stock.py` is superseded and the docs still recommend it.**
   It reads the community `yaqwsx/jlcparts` mirror, which `check_stock.py`'s header records
   covered **55 of the same 68 lines as NOT FOUND** when measured on 2026-09-18 — upstream
   has not rebuilt it. `check_stock.py` asks `jlcpcb.com`'s own parts endpoint instead and
   is the one the gate runs. `docs/BUYING.md` and `docs/HISTORY.md` still describe
   `check_lcsc_stock.py` as *"live, all 48 codes"*, which is stale twice over: the mirror is
   empty and the BOM has 56 distinct codes, not 48.
